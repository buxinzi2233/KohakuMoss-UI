# 训练主页

主页参考 GitHub profile 的展示项、活动日历和活动时间线结构，继续使用
Kohaku、Soul、Teletype 各自的颜色、控件和面板规则。

- **自定义展示**：选择最多 6 条训练记录作为 LoRA 展示卡。选择顺序即展示顺序；
  点击卡片介绍可编辑说明。筛选只隐藏候选项，不会清除勾选，取消不会保存。
  点击卡片底部的参数区域或「查看训练参数」，直接打开这次训练保存的完整配置；
  参数页可筛选，缺少保存配置的训练会明确显示不可用。
- **训练日历**：默认显示最近一年；右侧年份导航读取对应完整日历年。
  无活动年份仍显示日历，当前年份的未来日期不计入统计。窄窗口内日历单独横向滚动。
- **训练动态**：数据集是一级分组，训练记录是二级分支，按最近训练时间排序。
  同时使用多个数据集的训练会显示在各个数据集下。分组来自训练目录保存的
  `config.json`，不会根据训练名称猜测；旧的字符串路径和新的对象形式都支持。
  没有记录数据集的训练进入「未记录数据集」。
- **Civitai 收录**：设置帐号后，主页在后台自动查询帐号的 LoRA 模型列表。
  使用现有缓存，主页「刷新」会重新查询；查询期间仍可使用本地主页。
  根据训练名或导出文件名匹配 API 记录，训练动态并排显示训练状态和只读发布标签：
  匹配成功显示「已发布」并链接到模型页；成功查询但未匹配显示「未发布」。
  「未发布」仅表示该帐号的模型列表没有名称匹配，不是对全站发布情况的证明。
  查询期间显示「查询中」；未连接、查询失败、重名歧义显示「发布未知」。
  查询失败时收录数可保留上次统计，但记录标签不会继续显示为已确认。
  不再提供手动发布标记或历史中的展示状态控件，旧的手动元数据保留但不参与判断。

UI 的 `profile.json` 增加 `pins: [{run, note}]`。读取旧 `favorite` 时兼容为一个
展示项，不会因读取而写文件；保存时同步第一项到旧字段，空列表不会恢复旧收藏。
不修改训练器或训练目录。`GET /api/heatmap?year=2024` 支持按年份读取，默认窗口不变。
